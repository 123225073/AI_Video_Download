# 0.8.3 视频号连接与作者读取修复

本次在 0.8.2 基础上修复实际定位的连接和恢复问题。保留已有视频播放、校对、二创、图文流式分页及默认不生图。第三方微信作者列表的真实验收未通过，不宣称彻底修复。

## 已确认原因与修复

- 页面 WebSocket 在线不等于当前请求仍经过采集器。取消在线快路径，每个自动任务仍持有独立临时分流租约；已经就绪的页面不重复打开。
- Windows Clash Verge 服务模式使用 production 管道，配置可能保留同一实例的 sidecar-release 管道。仅在完整 64 位实例身份匹配时选择实际存在的本机 production 管道，配置不改写；不匹配身份、嵌入身份及远程管道拒绝。
- 原分享解析动态加载 axios，依赖官方域名下由本机组件提供的资源。新分享解析采用固定同源 native fetch，超时 10 秒，原生字符串作品 ID 校验后原样使用，数字和对象不能转换成稳定 ID。
- 分流规则不能改变已建立 HTTPS 连接的旧路由。实机观察到专用分流组健康且选中 Local，微信仍有 93 秒前建立的 DIRECT 连接。新代码只关闭精确 channels.weixin.qq.com、TCP、未经过本机采集器且拥有合法 UUID 的旧连接；不会调用全连接清理，不重启 Clash，不关闭 Codex 或其他域名连接。
- 新建恢复记录受本机文件保护影响，Node 可读到 TSD 封装而 PowerShell 正常读取。当前租约结束使用内存模式；PowerShell 将已验证对象通过 UTF8 内部 stdin 交给打包恢复工具，避免 Node 重读新文件；历史记录读取提供只读 phase/mode 路径。没有修改文件保护策略，没有导出凭据或恢复记录正文。
- 最后成员取消后，检查共享取消状态再进入后续变更；已发出的变更完整等待后再恢复，不将取消和恢复与迟到写操作竞争。
- 作者头像和名称不足以确认身份，缺稳定作者 ID 的结果明确为 pending。作品分页使用真实作品标识和已取得资料，取消逐项必须获取分享链接的步骤；失败保留清单、缓冲和游标。
- 作者页新增明确刷新弹窗、剩余等待、打开官方页面、继续检测和停止保留入口。检测复用当前任务，过期不会无限等待。

## 最终本地验证

- 核心串行测试 735/735 通过。实际 Electron 原视频播放测试单独独占运行 2/2 通过，总计 737 个测试用例；先前并行真实验收期间一次播放夹具启动超时，独立重跑通过，不隐去这次环境失败。
- 路由定向测试 21/21，连接 43/43；包括 Codex/其他域名连接保留、共享取消、旧连接精确选择、失败恢复、管道身份边界和等待倒计时。
- 新增实际 child stdin 与 PowerShell AST/只读状态测试 11/11；打包 Node + 磁盘恢复 helper 对独立 production 管道夹具恢复成功，原节点选择、中文节点、DNS、端口和规则保留。
- UI 离线实际 React 测试 11/11，指引弹窗、继续检测不重复启动、停止及失败保留通过。
- 多 Agent 对抗审查发现 4 个 P2，均已修复并定向复核关闭；仅审本次改动。
- 原有 80 条业务/配置记录、86 个媒体文件哈希基线保持，数据库备份保留。

## 真实微信边界

本机专用资源通过采集器返回明文 v4，新建视频号连接实际经过 Local；这些仅证明资源和分流可用。微信接口探针仍返回旧 v3，真实分享作者稳定 ID 和作品列表未通过。旧适配在同一个 JS 上下文内不能靠重复加载脚本热替换；保留整页刷新与明确失败指引，不尝试绕过旧 handler 标记。

限时测试退出后分流规则恢复。多个批次四项系统代理存在状态和值相同；有一批观察到 ProxyOverride 在运行中发生变化，程序保留较新设置，没有强制回写旧值。其后批次代理与规则均恢复。新诊断仅记录发生变化的白名单字段名，不输出字段值。

没有调整全局节点、模式、DNS 或重启 Clash；未关闭其他网站连接。不能把网络恢复成功、资源字节正确或头像显示，表述为微信作者列表已通过。
