# 安装、源码部署与打包（0.8.12）

普通用户请使用完整 `FengshaVideoDownloader-0.8.12-setup.exe`，包内自带下载工具、Node、Python 语音环境与两个离线模型。安装后自动准备专用浏览器连接（复用本机 Chrome / Edge），无需自行填写 IP 或端口。下面的开发环境和手工准备步骤只面向源码维护者。新版说明见 [稳定性与自动部署](搜索自动恢复-0.8.12.md)，验收见 [0.8.12 验收](验收-0.8.12.md)。

本版打包前必须通过 `scripts/verify-runtime.mjs`：检查完整资源和固定采集器校验值，并在隔离开发环境路径后实际运行下载、视频和语音组件；检查不通过即停止生成安装包。

0.7.0 提供独立的视频复刻工作台，公开分享链接下载后转录、校对，复用本地视频与任务，旧缺失媒体记录立即提示补充来源，不再连接微信等待。见 [0.7.0 验收与实测范围](验收-0.7.0.md)。

0.6.9 使用并列创作页签与紧凑参考选项；文案默认轻微润色并保留原意、钩子、口吻和格式。YouTube 时间筛选和日期核验已更新，抖音验证提示与微信自动打开尝试／连接提示已补齐。实测和未确认范围见 [0.6.9 验收](验收-0.6.9.md)。


本文面向另一台 Windows 电脑的首次部署。源码仓库不携带大型二进制、模型、用户数据库或账号；仅克隆代码不足以执行完整下载与本地转录。

## 1. 选择安装方式

| 方式 | 适用对象 | 前提 |
| --- | --- | --- |
| 完整 Windows 安装包 | 普通使用者 | 取得可信的 `FengshaVideoDownloader-0.8.12-setup.exe`，运行安装并从快捷方式打开 |
| 源码运行 | 维护、调试或自行构建 | 安装开发环境、下载 bin 组件、构建前端、启动 Electron |
| 自行打包后安装 | 分发给有权限使用的电脑 | 在 Windows x64 上准备完整组件及语音模型，运行 `pnpm dist` |

0.8.12 本地交付包位于 release/0.8.12，下载入口见 [v0.8.12 Release](https://github.com/123225073/AI_Video_Download/releases/tag/v0.8.12)。私有仓库下载需要账号访问权限。安装包包含 CLI、下载组件、本地语音环境与模型；源码仍需按下文准备。自行重建的文件不应期待相同哈希。

## 2. 开发环境

- Windows x64。项目包含 `.exe`、Windows 加密、代理和证书恢复代码，仅提供 Windows 构建配置；没有 macOS / Linux 完整适配验收。
- [Git for Windows](https://git-scm.com/downloads/win)。私有仓库需登录具有访问权限的 GitHub 账号。
- [Node.js](https://nodejs.org/en/download)：建议 22 系列，至少 22.12（Vite 7 的要求见[官方指南](https://vite.dev/guide/)）；本项目第三方独立 Node 运行时记录为 22.22.3。
- [pnpm](https://pnpm.io/installation)：10 系列，本文使用本机已验证的 10.13.1。
- Windows .NET Framework C# 编译器：`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，`pnpm build` 用它生成 `collector-native.dll`。缺失时需要补齐系统组件，不必修改系统安全策略。
- 准备本地语音时另需 [Python 3.12 x64](https://www.python.org/downloads/release/python-31210/)，含 pip。下载功能本身不要求外部 Python。
- 下载依赖、工具与模型需要联网并留出足够空间；模型、运行时、依赖、打包中间文件和最终安装包均占用空间。

在 PowerShell 执行：

```powershell
git clone https://github.com/123225073/AI_Video_Download.git
cd AI_Video_Download
npm install --global pnpm@10.13.1
pnpm install --frozen-lockfile
```

项目 `.npmrc` 仅设置 `node-linker=hoisted`，用于与现有 Electron 打包方式一致的依赖布局。`package.json` 已允许 Electron / esbuild 安装脚本。不要用 `--ignore-scripts` 跳过首次 Electron 准备。

## 3. 准备下载与视频号组件

### 目录要求

将上游包中的文件放到以下位置，不能只安装到系统 PATH：主进程使用这些固定路径启动组件。

```text
bin/
  yt-dlp.exe
  ffmpeg/
    ffmpeg.exe
    ffprobe.exe
    LICENSE.txt
  node/
    node.exe
    LICENSE
  collector/
    wx_video_download.exe
    LICENSE
    collector-native.dll      # pnpm build 自动生成
    collector-system.ps1      # pnpm build 从 electron/ 更新
  wechat/
    download-link.cjs          # 仓库已提供
    decrypt.cjs                # 仓库已提供
    LICENSE-*.txt              # 仓库已提供
```

| 组件 | 官方获取位置 | 操作 |
| --- | --- | --- |
| yt-dlp | [官方 Releases](https://github.com/yt-dlp/yt-dlp/releases)、[安装说明](https://github.com/yt-dlp/yt-dlp#installation) | 获取 Windows x64 `yt-dlp.exe`，放到 `bin/yt-dlp.exe`；保留并核对上游校验记录 |
| FFmpeg / ffprobe | [yt-dlp FFmpeg-Builds](https://github.com/yt-dlp/FFmpeg-Builds/releases) | 选择 Windows x64 包，解压并将两个 exe 放到 `bin/ffmpeg/`，保留对应许可证。历史本机版本为 N-126314-g3386acd2f9-20260829，新版本需自行验证 |
| 独立 Node.js | [22.22.3 官方目录](https://nodejs.org/download/release/v22.22.3/) | 获取 `node-v22.22.3-win-x64.zip`，将 `node.exe` 与 `LICENSE` 放到 `bin/node/`；即使电脑已安装 Node，也需要这个固定路径 |
| 视频号组件 | [v260907 Windows x86_64](https://github.com/ltaoo/wx_channels_download/releases/download/v260907/wx_video_download_v260907_windows_x86_64.zip) | 解压，将 `wx_video_download.exe` 放到 `bin/collector/`；使用普通 x86_64 包，不使用 safe / ARM64 包 |

视频号组件版本固定：程序会校验可执行文件，不可直接用上游最新版替换。

- 上游 ZIP SHA256：`2d4903ed994292ffa1ad019f8524c7b0bf37c25e0966a2e7903de90f3fb678ab`。
- 解压后 exe SHA256：`26a99c72dc1873982671426af2b60a20ceef9f7bb31e47fb7db42f94de45a818`。

```powershell
Get-FileHash .\bin\collector\wx_video_download.exe -Algorithm SHA256
.\bin\yt-dlp.exe --version
.\bin\ffmpeg\ffmpeg.exe -version
.\bin\ffmpeg\ffprobe.exe -version
.\bin\node\node.exe --version
```

仓库保留组件许可证；如果选用了不同 FFmpeg / Node 构建，以实际获取包的许可证为准。不要把别人的账号、Cookie、证书或私钥一起复制进来。视频号证书和工作目录由首次准备连接生成，源码构建本身不会连接微信或切换代理。

## 4. 准备本地语音（需要本地转录时）

脚本准备 Python 3.12.10 嵌入式运行时、Faster-Whisper 1.2.1、PyAV 15.1.0 和 base / small 模型，运行时使用 CPU。首次从上游下载；已有模型可复用缓存。

使用已安装的 Python 3.12 执行：

```powershell
py -3.12 -m pip install huggingface-hub
py -3.12 scripts/prepare-asr.py
```

如果安装时未启用 `py` 启动器，可使用 Python 3.12 的绝对路径替代 `py -3.12`。脚本安装语音 wheel 时要求主机 Python 3.12，避免把其他 Python 版本的二进制包装进 3.12 嵌入式环境。

生成位置：

```text
bin/asr/
  transcribe.py               # 仓库已提供
  runtime/python.exe
  runtime/Lib/site-packages/
  models/base/model.bin
  models/base/config.json
  models/base/tokenizer.json
  models/base/vocabulary.txt
  models/small/...            # 同类模型文件
```

模型来源：[base](https://huggingface.co/Systran/faster-whisper-base)、[small](https://huggingface.co/Systran/faster-whisper-small)。每个模型目录需要完整文件，不能只复制 `model.bin`。

已准备运行时、语音库且本地缓存有模型时，可以执行 `py -3.12 scripts/prepare-asr.py --offline`。离线参数不下载缺失的运行时或 wheel；缺失时会提示，不声称空电脑能够离线部署。

验证：

```powershell
.\bin\asr\runtime\python.exe -c "import faster_whisper, ctranslate2; print('ASR runtime ready')"
node scripts/asr-smoke.mjs
```

也可暂不准备本地语音，使用明确支持 `audio/transcriptions` 的在线语音服务；文稿 / 字幕导入仍可使用。文本 AI 模型列表可读取不代表其支持语音。完整功能安装包应准备全部运行组件、base 和 small。

## 5. 构建与启动

```powershell
pnpm build
pnpm start
```

`build` 先编译 Windows 辅助组件，再生成 `dist` 前端。`start` 清理影响 Electron 启动的 `ELECTRON_RUN_AS_NODE` 环境变量并启动桌面窗口。`pnpm dev` 仅用于前端调试，不能代替完整桌面程序。

首次启动在“设置 → 应用与组件”检查四个下载组件；在“设置 → AI 模型”检查本地语音环境。先用自己有权限访问的一条视频验证，再扩大批量。

## 6. 本地检查与打包

```powershell
pnpm check
pnpm test
pnpm test:e2e
pnpm test:settings
pnpm test:cli
# 本地语音与模型已准备时：
pnpm test:manuscript
# 全部组件完整时：
pnpm dist
```

| 命令 | 作用与边界 |
| --- | --- |
| `pnpm check` | 主进程核心模块语法检查与 Vite 构建 |
| `pnpm test` | 核心逻辑、账号、队列、作者读取、连接守护、转录与时间戳等自动测试 |
| `pnpm test:e2e` | 隔离资料目录，用合成视频验证下载、媒体、去重、账号和设置；不代表真实平台验收 |
| `pnpm test:settings` | 隔离目录与模拟 AI 服务检查设置分类、保存、跳转和重启；证书 / 代理操作用替身 |
| `pnpm test:manuscript` | 隔离目录验证实际本地中文音频转录、模拟模型矫正 / 翻译、目录、导出和恢复 |
| `pnpm test:cli` | 隔离资料、冷启动、真实合成视频下载与解码、桌面共享、分页、异步、暂停恢复、JSON 输出 |
| `pnpm dist` | 构建 Windows x64 NSIS 安装包；`--publish never`，不对外发布 |

本版交付输出：`release/0.8.12/FengshaVideoDownloader-0.8.12-setup.exe`（打包时指定 `--config.directories.output=release/0.8.12`）。一键安装到当前用户，创建桌面及开始菜单快捷方式，卸载配置不主动删除应用资料。运行安装包会影响当前安装，日常源码验证无须重新覆盖安装。

安装目录根部另有 fengsha-cli.cmd，调用包内 resources/bin/node/node.exe 与 resources/cli/fengsha.mjs。源码命令为 node cli/fengsha.mjs。两者默认与桌面共享资料；可用 --data-dir 建立隔离环境。详见 [CLI 文档](CLI使用说明.md)。

## 7. 配置与使用

- 默认源码资料：`.local/用户数据`；下载：`.local/下载视频`。
- 0.8.12 新安装资料放 `%LOCALAPPDATA%\FengshaVideoDownloader\用户数据`，默认下载为系统“视频”目录下的“风沙下载”。已有安装的旧资料库与已保存下载目录保持原位；桌面和 CLI 一致，不使用开发者的 D 盘路径。
- 下载无需 AI 密钥。文本矫正 / 翻译配置在“设置 → AI 模型”，默认 CPA 地址 `https://cpa.fengsha.online/v1`，可改为自己有权使用的兼容服务。
- 文本请求支持界面选择的 Chat Completions / Responses 协议。服务地址必须与实际 API 兼容，模型名称由服务目录或手动输入确定。
- 密钥由本人在界面输入，保存并读取模型、选择模型、测试连接。更换服务域名需重新填写密钥。
- 视频号需本机微信及正常可访问的视频号页面，任务期间可能临时切换证书与代理；“组件已准备”不代表微信已连接。
- 平台登录在“账号管理”完成。视频号连接、平台账号、文本 AI 和在线语音是不同配置，不能互相替代。

具体操作见[使用说明](使用说明.md)。

## 8. 备份、升级与故障

升级前退出程序，备份完整 `用户数据`、下载文件及其实际位置。保留 `library.sqlite`、`accounts`、AI 加密文件、转录原文及结果。不要将它们提交到 GitHub。更换下载目录不自动搬文件；加密账号或密钥跨 Windows 用户 / 机器恢复时可能需重新配置。

| 现象 | 处理 |
| --- | --- |
| `Missing Windows collector interop assembly` 或编译器不存在 | 在 Windows x64 检查 .NET Framework 编译器，重新执行 `pnpm build` |
| 下载组件缺失 | 核对第 3 节固定路径；系统 PATH 中有工具仍不足以替代 |
| Electron 启动失败 | 先构建，再用 `pnpm start`；确认 Electron 安装脚本已完成 |
| 本地模型未准备好 | 检查 runtime 与完整模型目录，运行语音准备脚本或配置在线语音 |
| 视频号校验失败 | 使用固定 v260907 普通 Windows x86_64 包，并核对 exe 哈希 |
| 微信连接不成功 | 重新进入微信视频号页面，检查本机 2022 / 2023 端口与连接状态；恢复原网络后重试 |
| 正在使用 PAC / 复杂代理 | 在视频号高级选项采用手动连接，原代理不直接覆盖 |
| 平台登录 / 验证 / 限流 | 官方窗口重新登录或验证，等待冷却，降低并发后重试 |
| 依赖文件读取异常 | 此机器历史存在透明加密读取问题；仅确有相同问题时使用 `node scripts/normalize-runtime.mjs` 处理项目生成依赖，不改系统策略 |

此文说明的是可执行的准备路径；本次交付的验证范围以 `验收-0.8.12.md` 为准，未把“本机隔离环境验证成功”描述成另一台全新电脑已实测。
