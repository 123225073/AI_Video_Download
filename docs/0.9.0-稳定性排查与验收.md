## 这次修了什么

| 场景 | 复现的问题 | 新版处理 |
| --- | --- | --- |
| 下载长视频、中文文件名 | 引擎按数据块解析输出，可能拆开中文字符或漏掉同一块里的多行；长进度可能耗尽输出容量 | 按流解码、逐行识别进度和最终路径，下载进度单独处理 |
| 重试与已有文件 | 同一作品的旧失败任务和新任务可能同时写盘。空文件可能被认成已下载 | 同一作品避免冲突写入。按真实文件类型、长度及已有记录判断能否复用 |
| 评论较多 | 页面已经加载超过 2000 张评论卡片时，旧读取器可能漏掉后续评论并报告已到末页 | 分批处理已加载的卡片。浏览器夹具的 2101 张卡片全部读出 |
| 评论续读 | 完成后返回的忙碌状态可能锁住操作。相同上限可以空跑。已到末页的缓冲在重启后还可能重新联网 | 结束后解锁，续读要求提高已读数量的上限，已确认末页的缓冲可离线恢复 |
| 搜索评论 | 评论与用户视图的匹配范围不同，大量匹配项一次性展示。无 ID 的同文评论可能被错误合并 | 评论、昵称、地区和用户 ID 支持多词同时匹配，统一全半角和大小写。按每页 50 条显示，并区分可辨别的匿名昵称 |
| 私信准备与重试 | 点击第二条评论也可能引用第一条；评论内的模板符号会二次替换；提交响应丢失会让界面仍像可以再发 | 使用所点评论，原文按字面填入。提交不确定时提示核对聊天记录。批量执行前再次检查已尝试的用户与文案 |
| 窗口与导航 | 首页后台加载多个工作区，评论历史入口深。关闭窗口可能打断正在运行的搜索或联系任务 | 按首次访问加载工作区，保留搜索输入。左侧可直达历史评论。任务运行中关闭会先询问 |

## 日常使用

1. **找作品**。在“作品搜索与二创”选择平台，输入关键词和日期范围。要保留平台未返回日期的作品，可勾选“同时列出日期未知作品”。
2. **找评论**。选中作品后点击“一键采集评论”。以后可直接进“评论与私信”，从“采集记录”选回之前的作品。筛选框查的是该份记录中已经采到的内容。
3. **按人核对**。多个词用空格隔开。需要联系某条评论的作者时，从该评论行准备单独私信。批次按用户去重，先检查每位用户的预览文案。
4. **遇到中断**。先看本条记录的提示和已采数量。达到上限可提高上限继续；官方要求登录或验证时，在对应账号的官方窗口处理。私信显示已尝试或待核对时，到官方聊天查记录。

## 验证与仍需跟进的问题

- 本机 HTTP 测试视频经过真实下载引擎、合并工具和媒体校验，已验证加入队列、保存、播放解码、重复跳过及重启后的资料读取。
- 评论与私信使用隔离样例。覆盖首批显示、中断续读、历史切换、多词匹配、重复收件人、第二条评论引用、停止续跑和提交结果不明。真实对外发送为 0 条。
- 10 个导航入口在 1080 × 720 窗口完成切换与横向溢出检查，另核对了常用尺寸的下载页和评论页。外部平台登录状态、限流、页面结构和消息送达仍由平台决定。
- 视频号连接的三条既有测试仍与已安装旧版的行为存在差异。页面延迟进入或不支持工具栏自动刷新时，旧版只延迟重检一次，随后可能要求手动刷新；测试期望继续探测或自动重开微信入口。后续应在能复现的真实微信版本上记录窗口出现时间与刷新结果，再决定调整连接行为。
- 本机主资料库升级前约为 7.7 MB。源码会在部分进度更新时同步导出完整数据库。若大批量采集时仍有界面停顿，值得用同一份记录测量每次保存耗时、频率及界面响应，再确定是否需要合并写入。此次没有实测数据可将历史卡顿归因于存盘。
