# 商业化稳定性审查与本次交付

本次已完成 0.8.11 的实现、回归、完整打包、原位安装、真实媒体播放和数据保留验收。软件自身的重复接入确认和部署问题已有实质改进；外部平台限制、发布者身份及客户环境覆盖尚不能承诺完全消除。

## 已确认并修复

| 影响 | 确认原因 | 0.8.11 处理 |
| --- | --- | --- |
| 重启软件后 Chrome 反复要求接入确认 | 旧模式接入用户日常 Chrome，浏览器自身需要重新允许 | 新安装默认独立持久浏览器，自动发现并启动 Chrome/Edge，自动管理回环端口；旧账号可一次切换并保留原会话线索 |
| 返回软件还需点击完成登录 | 界面只有手动检测入口 | 返回软件自动检测，只在官方页面确实已登录时保存成功；手动检测仍可用 |
| 浏览器切换、关闭及重复点击偶发失效 | 旧连接延迟关闭事件误清新标签；重复开页及旧登录结果存在竞态 | 增加连接/标签/模式身份核验及并发复用；实际失败回归已修复 |
| 某些机器安装后缺组件 | 原打包允许缺少二进制或模型仍完成 | 完整资源、固定采集器哈希、独立环境运行及两个模型离线加载必须通过，失败阻止打包 |
| 安装位置影响保存权限 | 资料目录固定在程序上一级 | 新用户使用当前用户专属资料目录，旧库不迁移；不可访问明确报错，不创建空库掩盖问题；CLI一致 |
| 打开软件长时间无窗口 | 创建主窗口前串行等待历史网络恢复 | 先显示界面，后台恢复；视频号操作与退出等待同一恢复任务，失败保持错误 |
| 微信连接误以为每次要点确认 | 文案要求“已操作，继续检测”，实际后台已自动检测 | 明确自动等待和自动继续，人工检测作为可选辅助 |
| 简单代理在别的电脑报错 | Windows分协议地址和IPv6没有正确解析，异常端口反而可能通过 | 支持等价HTTP/HTTPS端点与有效IPv6，严格验证端口、路径和回环；复杂代理不擅自接管 |

## 仍会影响商业分发的事项

| 优先级 | 剩余事项 | 当前边界与下一项验收 |
| --- | --- | --- |
| 高 | 发布者签名 | 安装包目前未签名，可能出现未知发布者/SmartScreen。需所属主体的代码签名凭据；本次未购买证书、改变信任策略或对外发布。 |
| 高 | 独立客户机器验证 | 本机做了全新资料及隔离开发环境测试，没有第二台干净电脑。需覆盖Windows普通用户、中文用户名、安装目录变更和常见公司/家庭网络。 |
| 高 | 平台登录及访问限制 | 本版未重新验收五个平台的所有真实登录和采集。验证码、扫码、Google安全验证、平台限流/IP限制不能替用户绕过。 |
| 高 | 多账号备注共用一个外部浏览器身份 | 当前多个同平台账号备注不等于独立登录身份。界面已明确说明；若产品要销售“同时多账号独立作业”，必须另行实现逐账号浏览器隔离并完成真实多账号验收。 |
| 中 | 浏览器和微信外部前提 | 完整包不要求Node/Python/FFmpeg开发环境，但专用浏览器复用电脑现有Chrome/Edge。两者都不存在时会提示安装，未静默部署系统浏览器。微信采集仍需本机微信及登录。 |
| 中 | 微信插件、端口及复杂代理 | 微信2022/2023端口占用、PAC、不同协议不同代理、微信插件自动刷新不支持等场景仍可能要求处理。保留原网络和人工入口，不关闭其他软件解决冲突。 |
| 中 | 旧媒体失效记录 | 本机媒体库7条旧记录指向缺失文件，记录在升级前后未变；当前没有来源材料可恢复，未删除。仍在的视频工作台原视频实际可播放。 |

“网络IP”尚不是已查明的统一故障名，源码也没有对应统一报错。现已证实并修复本机连接参数及一类代理兼容问题；若其他电脑仍出现IP提示，需按该提示发生的平台与实际错误区分本机连接、代理、登录和平台限流，不能把所有情况都归为安装没部署好。

## 使用与交付

普通使用者只需取得 `release/0.8.11/FengshaVideoDownloader-0.8.11-setup.exe` 安装。新安装自动使用专用浏览器；本机已有5个账号保持原选择，在“账号管理”选择一次“使用专用浏览器（推荐）”，之后在其官方页面首次登录。原有浏览器登录仍保留，可切回兼容模式。

本轮954项全量回归通过，浏览器最后54项定向回归通过；安装后的2,652文件、836条资料、100个素材文件完成校验，原视频实际播放，两个本地模型可离线加载。清理旧包和生成目录释放约2.68GB。CLI完整自动化受本机透明加密影响未通过，详见[验收记录](验收-0.8.11.md)。

本版仅本地交付，没有GitHub发布。完整操作说明见[稳定性与自动部署](稳定性与自动部署-0.8.11.md)。
