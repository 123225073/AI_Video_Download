# 公众号作者批量二次审查（0.8.13-local.5）

用户确认本机不能登录电脑微信，并要求完成开发后由其后续真实测试。因此，本次验收分为自动化检查及真实平台限制，不将两者混为“所有功能已经实际可用”。

## 真实失败已复核

用户完成公众平台登录，后台账号登录可用。账号搜索接口能返回“编程进阶录”及 fakeid `MzkwNjQ0MTIzNA==`，与原文 biz 一致；自身账号的原生文章列表返回 `ret:0`。请求目标外部账号时，旧 `/cgi-bin/appmsg` 和当前 `/cgi-bin/appmsgpublish` 均真实返回：

```json
{"base_resp":{"err_msg":"freq control","ret":200013}}
```

对照原生网页请求补齐 AJAX 头及实际页面生成的 fingerprint 后，外部账号请求仍被拒绝。该证据只能证明该会话的此项请求受到平台限制，无法单凭错误码确定是短时频控、账号能力还是其他平台规则。后台原生“转载文章”搜索返回其他公众号，不能当作该作者的文章。软件没有把这些无关搜索结果加入用户清单。

## 本次改动

1. 采用当前 `appmsgpublish` 发布列表接口；正确解析外层 `publish_page` 和逐条 `publish_info` JSON。保留旧响应格式的解析兼容。
2. 按发布记录推进服务器偏移，按文章展示清单；一次发布的多篇文章全部保留。超出本次文章数量上限的条目存入余量，继续读取时先消费余量，不跳页。
3. 对真实 `200013` 有限冷却，20/40秒后重试当前页，最多三次请求。持续拒绝后，本机阻止一分钟内再次立即请求。支持停止，界面显示冷却进度。没有宣称这个策略能够解除微信服务端限制。
4. 每页成功后立即写入发现记录。中断和后续页失败均保留已取得的页、余量和偏移。
5. 对同一批次及跨批次的重复页拒绝推进偏移；对损坏的发布 JSON 拒绝静默跳过。
6. 保留公众号身份校验、封面来源校验、只识别不归档、扫码会话隔离及凭证不进入渲染记录等保护。

当前接口格式参考：[wechat-mp-article-list 的当前后台工作流](https://github.com/Alex-giao/wechat-mp-article-list/blob/main/references/backend-workflow.md)。未复制其代码。

## 验证范围

相关单元测试15项通过，覆盖真实错误码识别、三次请求上限、20/40秒延迟、等待中取消、嵌套JSON、多篇发布、身份冲突、空页、损坏响应、重复页、保存与重试。

作者流程界面检查覆盖自动识别、后台无弹窗、未授权零结果、账号范围、分页、保存、失效重连、批次失败保留、凭证隔离、发布余量、冷却拦截、停止后已读页保留及同批重复页。其结果属于隔离的官方域名响应样本，不能代替真实目标账号获取成功。

一次隔离测试在早期读取临时数据库时出现 `no such table: records`；检查该轮两份磁盘数据库均存在 `records` 和 `metadata` 表，独立重新运行完整流程通过。没有依据把这次未复现现象归因于业务改动，也未因此修改用户数据库结构。

本机没有运行电脑微信，用户授权暂缓客户端真实测试。公众号客户端历史文章路线尚未验证及接入；未新增未经验证的系统代理、证书或微信进程自动化。

结论：本次代码和可运行的自动化检查可验收；用户当前外部公众号列表的真实获取仍受平台拒绝，不能标记为已完成真实采集或整号历史验证。
