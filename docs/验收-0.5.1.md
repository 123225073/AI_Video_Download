# 0.5.1 视频号连接与 Clash 共存验收

## 修复内容

- 视频号用户搜索和继续读取通过连接管理器，先准备服务与连接再请求搜索；界面显示连接进度。
- Clash Verge 规则模式保持系统代理、内核、守卫和既有节点选择，只临时增加 channels.weixin.qq.com 分流。
- 采集子进程隔离继承的代理环境，避免 Codex 的 HTTP_PROXY 把请求送回采集器；其他程序的环境不变。
- Windows 专用证书改用标准信任流程。原注册表直接写入会被受保护证书库移除，不能据此判断已经信任。
- 独立恢复守护清理分流与本次证书，停止孤立的采集端口；修改期间检测用户规则变化，避免覆盖新配置。
- 更新连接设置、图文说明、YAML 第三方许可和打包恢复辅助程序。

## 验证结果

- 127 项自动测试通过，包括任务共享、取消/超时、代理被其他程序改变、Windows 子进程树终止、代理环境隔离、守卫开启时分流、同数量但不同规则不被覆盖、真实 IPv6/逻辑规则格式和解析错误不回显凭据。
- 五个平台隔离桌面交互通过：搜索、稳定身份、分页、验证时保留结果、导航保留输入、小窗口、CLI 复用和不自动下载，无前端异常。这不是五个平台真实登录验收。
- 本机真实 Clash Verge 2.3.1 / Mihomo v1.19.10：视频号 HTTPS 证书链校验成功，返回 HTTP 200 和注入后的页面；同时访问 GitHub HTTP 200；原节点选择保留，Windows 系统代理值不变；正常结束移除规则。
- 强制终止真实任务进程：独立 PowerShell 守护通过包内 Node 恢复辅助程序移除临时规则、保留原节点与系统代理、停止 2023 采集端口。此测试不向 Windows 添加证书，证书确认与真实微信登录单独验证。
- 图文截图为 0.5.1 的连接设置页面，未拿模拟用户结果当作真实微信搜索。
