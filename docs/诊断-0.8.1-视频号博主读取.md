# 0.8.1 视频号博主读取与 Clash 控制接口诊断

本轮仅诊断，未修改程序、Clash 配置、系统代理或证书。

## 已确认的当前故障

1. 下载器的 `ClashRoute.load()` 只接受 `127.0.0.1:端口`、`localhost:端口`等 TCP 控制地址。当前 Clash 生成配置的 `external-controller` 为空，实际使用 Windows `external-controller-pipe`。下载器因此直接抛出截图中的“Clash 本机控制接口不可用”。通过现有本机控制凭据只读请求命名管道，`/version`、`/configs`、`/rules`均返回 HTTP 200：内核 v1.19.32，规则模式，混合代理端口 7897，TUN 关闭，525 条规则。Clash 内核运行正常，问题是下载器未兼容当前控制通道。

2. 使用截图原链接 `https://weixin.qq.com/sph/AidY5tmMHd` 直接调用当前本机采集服务 `/api/channels/feed/profile`，HTTP 200、组件 code=0，但页面返回 errCode=1011、errMsg=“微信页面接口调用失败”，未取得作品或作者对象。实际读取失败，与截图相符。

3. 同时 `/api/channels/status` 返回 available=true，适配探测返回 fengshaAdapterVersion=3。当前探测只验证脚本能响应，没有检查详情、作者作品列表等实际能力；设置的“微信已连接”也只看 available。通信已连接被当成读取已就绪。

## 已定位的适配缺口

`collector-content.js` 对详情请求只在 `msg.data.oid` 存在时使用新适配；博主识别传的是 `msg.data.url`，会回到上游旧处理方法。关键词搜索、按作品 ID 读详情、从分享 URL 识别博主是不同调用路径，修复前两条不自动覆盖后一条。

运行实际适配脚本的隔离复现确认：URL 详情只调用旧方法，新详情方法未被调用；OID 详情则走新方法。旧方法抛出带 errMsg 的对象时，错误处理只读取 error.message，会丢失原错误信息并变成笼统的“微信页面接口调用失败”。真实微信旧方法内部具体失败函数或返回条件尚未确认，不能仅凭 1011 判定为微信版本更新、账号异常或验证码。

源码、安装版组件文件、运行服务的适配脚本文件 SHA-256 一致。当前系统代理仍是 127.0.0.1:7897，Clash 没有采集专用规则；最近三份租约均为已恢复。这轮证据不支持“需要关闭 Clash”“尚未恢复代理”或“只是旧安装包未更新”的解释。

## 为什么反复出现

连接提示没有区分通信、接口能力、实际请求结果；不同视频号入口依赖不同路径。上一轮 0.8.1 验收主要覆盖转录、二创、配图和原视频播放，未覆盖本次真实分享 URL 的博主批量识别。测试数量不能替代这条实际业务链路验收。

修复应针对下载器：兼容 TCP 与命名管道控制；补齐分享 URL 到作品详情、稳定作者 ID、作者作品分页的整条路径；按功能显示可用状态并保留可定位的错误；用本次失败链接验证真实作者识别和作品列表。不能只消除提示，也不能通过反复刷新、重新登录来代替兼容修复。

只读实测与隔离复现：`output/diagnose-082/live-readonly.json`、`output/diagnose-082/adapter-path.json`。未记录或输出控制凭据。
