# 0.4.2 对抗审查与真实验证范围

日期：2026-10-06。案例作者：理_不懂，UID 31321989。

本次审查覆盖列表请求、字段映射、分页与恢复、账号隔离、下载复用、CLI 等关键路径，并回归设置、转录与既有平台逻辑。不能据此保证整个产品不存在其他缺陷。

## 已确认的原因及修复

| 问题 | 证据与影响 | 修复 |
| --- | --- | --- |
| 来源请求头触发客户端拦截 | 同一视频详情接口，仅把 Referer 从源站根地址改成完整视频/主页路径，本机 Electron 即返回 ERR_BLOCKED_BY_CLIENT | 仅发送可信源站地址，排除路径和查询参数；代理与登录会话保留 |
| 访客请求与浏览器会话不同 | 应用未保存 B站账号；隔离官方主页弹出登录，访客列表被平台拒绝 | 明确应用内登录步骤；匿名直连公开列表使用独立 HTTP 请求，登录/代理仍使用对应应用会话 |
| 799、HTML 或缺失 data 被误报 | 接口实际出现“请求过于频繁”；HTML 产生原始 JSON 解析异常 | 正确分类799；无效资料不推进位置、不作为空的完整结果；不输出响应正文 |
| 排队取消等待上一个请求 | 排队请求取消后超过200毫秒仍未返回 | 取消立即结束，后续请求仍保持串行顺序 |
| 重复页及缩水页误判覆盖范围 | 伪造同一批视频到下一页、页内重复或未完成页数量不足 | 验证作者、页码、总数、条数与重复身份；失败保留位置，分页变化要求重读 |
| 切换账号混用旧游标 | 已读取清单后切换账号，旧位置被新账号继续使用 | 不拼接账号访问范围，明确从第一页重读 |
| 失败重读无法继续 | 原完整清单保留了 complete:true，界面不提供继续 | 失败结果 complete:false；保留旧清单并允许继续重读，显式新筛选仍生效 |
| 新空记录使旧清单难以找回 | 当前空记录与历史8条同作者清单同时存在 | 增加“恢复上次清单”，限定原作者和账号范围，保留原历史记录并明确历史性质 |
| 隐藏合集及非法数值破坏字段 | 合集未含BV时提前报错；Infinity、非法时分秒、溢出日期 | 正确跳过隐藏合集；无效时长/日期不进入可用字段，整批识别不因日期溢出崩溃 |
| 详情身份校验不完整 | av链接未核对返回aid；分P参数可为NaN | 核对BV/av、作者和有效分P |
| 信息补全清空已有字段 | 不完整详情覆盖原有封面/日期/时长；读取中切换账号 | 只合并实际取得的字段，保存补全进度，切换账号时停止 |
| 复用文件缺少CLI元数据 | 排队后文件恢复，任务完成却没有大小与时长 | 复用时保存实际文件大小、时长和画质，并落盘 |
| CLI超时预算被重置 | 入队等待和完成等待分别使用完整timeout，短超时轮询可等待30秒 | 共用一次等待预算，轮询使用剩余时间；超时保留任务ID |

没有更改全局安全策略、系统代理或读取普通浏览器的登录凭据。请求受平台限制时，不自动切换接口或连续重试。

## 真实平台边界

本次0.4.2真实新清单测试仍被 B站限制：作者身份正确，但新列表读取0条、状态为中断，显示中文提示而非“已读完”。不能把此前保存的8条或模拟55条当作本次新清单成功。应用访客官方主页也要求登录；应用内登录后的全量列表尚待本人完成登录后实测。

历史8条的实际信息与封面已有安装版实测，本次提供显式恢复入口；恢复结果会清楚显示“历史结果，并非本次新读取”。单视频能播放或详情可读取，不足以证明作者列表获准访问。平台作品数也不保证当前账号可访问整个历史。

接口参数参考当前 [yt-dlp Bilibili提取器源码](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py)。应用会话、代理及两种HTTP栈的区别参考 [Electron session文档](https://www.electronjs.org/docs/latest/api/session)。
