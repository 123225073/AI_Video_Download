# 0.8.5 视频号稳定读取与本机历史清除

详细故障分层、前次验收缺口和本次保证范围见 [反复失败原因复盘](视频号反复失败原因复盘-0.8.5.md)。

## 问题与修复

0.8.4 的安装与真实读取曾通过，但用户后来通过安装界面操作仍失败。再次实机复现两个具体问题：微信窗口在但 F5 未让页面接入；分流准备期间 Windows 的 ProxyOverride 在本工具未写入它的分流路径中发生变化（具体写入者未确认），原四字段基线检查把这个不由本工具修改的例外列表误判为代理入口变化，操作提前结束。读取异常只有短暂通知，界面随后恢复为按钮，看起来没有反应。

- routed 分流模式仍严格核对系统代理启用值、服务器和 PAC；不再把不修改的 ProxyOverride 作为启动条件，不写回该字段。普通系统代理模式仍保持四字段校验。没有放松权限、改变系统安全策略或接管全局网络。
- 读取失败原因保留在博主页，直到重新操作或更换输入。打开微信按钮立即反馈已发送请求，明确没有窗口时需手动进入。
- 指引改为微信视频号窗口菜单“刷新”，或关闭页面重新进入；不再假设 F5 在所有微信窗口都有效。已打开其他视频时仍按输入原链接核验作者。
- 新增博主历史清除：仅删除 creator 记录与 lastCreator 指针，清空当前输入和清单；活动识别/读取期间拒绝清除。
- 新增选定账号删除：退出本机独立会话，清除 Cookie、站点存储、HTTP 认证与缓存、加密备份和下载会话文件，再删除账号记录和对应活动账号指针。不会自动切换到另一个账号。处理延迟 Cookie 事件，避免已删除记录被恢复。正在使用账号的任务未结束时拒绝删除。

两项清除均有明确范围的确认弹窗；升级过程不会替用户清空真实资料。保留下载、媒体、转写、文案、配置及其他账号。

## 验证

- 修复后的源码候选通过实际 GUI 连续两轮识别“老头们的快乐生活”，每轮读取 50 条，4 个不同分页位置，50 个作品 ID 无重复，结果作者字段与请求作者一致；没有在两轮间要求用户反复刷新。使用真实微信连接，无模拟作者或列表。尚未据此宣称遍历全量或批量媒体下载成功。
- 连接与 PowerShell 恢复 50 项定向检查通过；代理例外变化回归先复现失败后通过。作者界面覆盖持续错误、打开按钮反馈、清除确认/取消/失败保护。
- 独立 Electron 清除验收：两个合成 B站账号，删除其一后 Cookie 为 0，备份及下载会话文件不存在，另一账号会话保持；忙碌期间拒绝删除；博主历史清空；重启后仍保持正确，独立文案不变。只使用隔离测试数据，无真实账号被删除。
- 完整串行测试 747/747 通过。构建打包退出码 0，静默安装退出码 0。安装后的 139 个 electron/dist 文件核对一致（electron/main.js 仅 CRLF/LF 不同），采集资源逐字节相同。
- 最终安装版通过实际界面再识别“老头们的快乐生活”，4 个不同分页位置读到 50 条，ID 无重复，结果作者字段与请求作者一致，无界面脚本错误；退出重启后仍显示 50 条。清除按钮存在、确认说明正确，真实资料没有执行清除。
- 最终任务结束状态 idle，Clash 规则哈希恢复一致，系统代理启用、地址和 PAC 保持。ProxyOverride 仍有独立变化，本次不修改也不覆盖它。采集端口停止监听。
- 原有 83 条受保护业务记录保留（账号正常验证时间可更新），86 个媒体文件哈希一致；4 个账号、6 个下载任务、6 个媒体项、12 个转写项保持。桌面快捷方式核对原安装路径并启动新版。

补充证据边界：固定组件的作者列表有 5 分钟缓存，连续两轮可能复用；分页位置计数不等于已经逐次证明源站新请求。条目缺失作者字段时沿用请求作者，未逐条独立取详情复核。详见复盘。
