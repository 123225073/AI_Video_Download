# 0.8.9：Chrome 登录与采集修复

网页登录默认使用本机 Chrome，搜索、博主页面及评论读取复用同一应用连接。原内置登录保留在“高级兼容”中；原有本地视频、转录、二创资料及内置下载会话继续保留。

## 登录为什么失败

截图中的“插入 USB 安全密钥”是 Google 发起的通行密钥验证，并不能单凭这个窗口认定程序错误。随后出现的“此浏览器或应用可能不安全”才表明：Google 拒绝了当前内嵌浏览器的登录环境。这不是增加超时时间就能解决的问题。

现在在“账号管理”点击“Chrome 官方登录”，使用 Chrome 自己的账号与登录环境。已有 Chrome 登录可沿用；需要登录时，在该官方标签完成，再返回点击“完成登录并检测”。不提取密码，不导出 Chrome Cookie，也不把 Chrome 登录复制到内置窗口。

Chrome 调试连接与平台账号登录是两件事。首次接入以及应用进程重新启动后，Chrome 可能要求本人点击“允许连接”；同一运行进程内复用连接。Chrome 连接成功不代表所有平台都已登录。多个账号备注共用当前 Chrome 身份，不具有独立的浏览器账号隔离效果。

原有只依赖内置会话的下载路径继续使用其原会话。新建 Chrome 账号不会凭空生成一份内置下载会话。内置兼容登录仅在用户主动选择时使用。

## 搜索和评论具体改动

- 修复 Chromium 错误页也触发 `dom-ready`、随后被误判为成功加载的问题。只接受已经提交的官方 HTTPS 页面，暂时连接失败最多重连一次，失败后关闭空白自建窗口并保留结果。
- 抖音官网正常入口已变为 `/jingxuan/search/…`。外置搜索从官网首页初始化，再操作可见搜索框和按钮。评论复用原搜索／博主标签，精确选中目标作品，核对地址作品 ID 和当前播放 ID 一致后才读取；不自动猜首条作品。
- 补齐抖音当前评论作者、正文、时间、地区、稳定编号及回复结构；自动打开所选视频的评论区，已有评论区不会重复收起。验证码或登录拦截交回官方页面，不自动绕过。
- YouTube 可在同一 Chrome 登录环境读取评论；登录返回后继续定位原作品。首批一直为空且没有验证拦截时，只在同一会话重载该视频一次；空返回不当作末页，已保存评论不丢失。
- 任务停止只影响本工具自建或借用的当前操作，不关闭用户浏览器，也不清除 Chrome 登录。借用搜索页面采集评论时，停止不销毁来源页面。

## 视频号检测及按钮

微信视频号位于官方 WMPF 插件进程，原来只核对微信主进程，会出现“页面已开却检测不到”。新版针对视频号 Document 精确检测，并核对腾讯签名、固定官方插件路径、与微信的进程亲缘和 HTTPS 页面地址。

任务连接准备完成后，才尝试该视频号页面原生“更多 → 刷新”；自动打开缓存页面后可再检测一次。刷新请求不算连接成功，仍须收到采集组件连接及本任务需要的实际接口。检测不支持时保留人工入口和停止按钮，结束恢复原网络。

“直接使用已采集内容”现在只使用本次搜索已取得的作品，显示数量，停止后续采集并退出等待提示。当前没有结果时不会借用旧二创稿来展示无效按钮。窗口打开失败及按钮执行错误会显示在当前提示中。

## 已确认的末页误判

视频号官方以 downContinueFlag 判断向下是否还有评论；末页仍可能有 lastBuffer。此前仅凭游标非空判定下一页，导致真实零评论被报异常。现在优先使用明确的末页标志；仅在旧响应没有该字段时沿用旧契约。平台 BaseResponse.Ret 非零先报实际错误；有下一页但暂时空的响应允许最多连续 3 页自动推进，重复游标立即停止并保留资料。

## 实际验证范围

- YouTube：本次通过应用后端连接现有 Chrome，实际取得 2 条评论、2 位用户；另一次启动曾空返回，因此增加上述一次性空批恢复。仅证明该公开样本可读取，不保证所有视频或所有分页。
- B站：本次应用后端取得首批 5 条评论；新 Chrome 账号检测依据官网 `nav.isLogin`，不凭头像占位确认成功。
- 抖音：官网正常交互链曾展示 10 条根评论及 3 条回复；官网视频分类和直接作品地址在当前网络下仍出现连接异常。按用户要求，公司网络下的应用真实连通性留待后续确认；本地回归通过不替代该验收。
- 视频号：本次手动刷新后真实搜索取得 5 条作品；最终应用后端对既有公开样本先取得 5 条评论，再继续至 60 条、29 位用户，实际请求 3 次，结束连接状态 idle、原网络恢复。另一个零评论样本的官方 Ret=0、commentCount=0、downContinueFlag=0，已据此修复末页误报。首次自动接入仍未通过无人工验收：最终精确查询在当前微信返回 unsupported-document-query，因此不能承诺今后不需手动刷新。
- 小红书及元宝：沿用当前官方登录状态与平台限制，本次没有新增真实平台验收。元宝网页登录用于原有视频号分享解析，和电脑微信的搜索／评论连接分别验证。
