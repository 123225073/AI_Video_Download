# 0.6.12 视频号克隆与已有任务恢复

## 已确认的问题

视频号搜索结果使用 `/web/pages/feed?oid=...&nid=...` 作品地址。旧转录流程在账号有保存的登录时，将它送入只支持公开分享链接的解析器，产生 `WECHAT_INVALID_LINK`，随后被界面显示成笼统的素材处理失败。真实详情请求又复现 `WXU.API.finderGetCommentDetail is not a function`：页面连接正常不能保证该接口已经被旧拦截器识别。

## 修改

- 搜索作品按原作品 ID 与 nonce 使用已有视频号采集连接和下载解密模块；公开分享链接保留原来的解析路径，缺失作品 ID 会明确拒绝。
- 从页面实际加载的官方模块恢复详情接口，保留原服务对象和调用上下文；返回作品 ID 必须与所选作品一致。
- 复用“风沙视频学习台”与本项目已有的下载、解密、FFmpeg 校验和本地转录链路，没有引入另一套媒体处理引擎。
- 搜索页顶部新增“我的克隆任务”。同一平台、同一作品再次点击默认打开已有稿件；运行中的任务也可以重新进入。只有明确点击“重新克隆这篇作品”才新建一份，旧稿保留。
- 原视频下载后立即保存位置。停止后继续转录复用该文件，完成后关键帧提取也能复用原视频。
- 视频号克隆等待微信连接时显示与搜索相同的可操作连接提示，并提供停止入口。

## 已通过验证

- 两处解析/详情失败及重复克隆行为均先通过回归复现，再修复；全部 **275/275** 单元测试通过。
- 原生 Electron 工作台验证：处理中返回搜索、顶部打开任务、卡片打开已有任务、页面重载、停止、继续和进程重启恢复；同一作品始终只有一个稿件，没有额外文本或图片模型请求。
- 使用原下载模块实际传输加密测试视频、解密并完整解码，随后提取真实音轨，通过隔离语音边界回填原文和成稿。取消后恢复只下载一次，保存的视频与原测试视频逐字节一致。该测试不代表真实微信平台成功。
- 正式打包程序显示 0.6.12、可启动，51 个后端源文件和渲染资源与已验证源码一致，窗口没有前端脚本错误。
- 本版包含 0.6.11 的视频号搜索接口识别与分页修复，先前真实搜索及安装验收见对应记录。

## 安装与真实平台边界

真实微信详情请求已复现旧接口识别错误。更新页面适配后，当时电脑微信采集连接仍未接通，真实新视频下载仍未验收，不把隔离测试当作平台验收。随后 0.6.12 已完成覆盖安装及已有任务重新进入、重启恢复验证；4,636 个升级前用户文件、122 条业务记录和 73 个稿件/转录素材文件核对一致，4 个账号、6 个任务、6 个媒体、8 份转录均保留。已有视频号 MP4 的实际本地 Whisper 识别通过，143 字、16 段。0.6.13 进一步纠正克隆流程：直接复用已采集说明和封面，不无条件再次查询视频详情；参见新版验收记录。

诊断连接均执行原代理恢复，并将诊断用定时刷新配置恢复为 0；未关闭 Clash。没有发送私信或发布自媒体内容。
