# 稳定性与自动部署（0.8.11）

普通用户使用完整 Windows x64 安装包，不需要安装 Node、Python、FFmpeg，也不需要填写浏览器 IP、端口或启动参数。平台账号仍需本人在官方页面登录。

## 此次核查与调整

| 问题 | 原因与处理 |
| --- | --- |
| 打开浏览器反复确认 | 原来接入日常 Chrome，应用重启会重新请求 Chrome 连接权限。新安装使用软件专用浏览器，自动发现 Chrome 或 Edge、准备独立资料目录及本机连接，重复打开复用会话。 |
| 旧用户已经登录，升级后如何处理 | 保留旧浏览器模式与原资料。在账号管理可一次切换“使用专用浏览器”；首次需在专用浏览器重新登录，之后保留会话。不复制或清除日常浏览器登录。 |
| 换电脑后提示组件缺失 | 原打包流程没有检查组件是否完整。本版在打包前检查完整下载、微信辅助、语音运行环境和模型，并在清除开发环境路径后实际启动组件；缺失或不能运行就停止打包。 |
| 安装位置变化导致无法保存 | 新安装使用当前用户专属资料目录，不向受保护安装目录写资料。旧资料库优先保留原位，无法访问时明确报错，不悄悄创建空库。 |
| 启动慢、看起来没有反应 | 原先网络恢复完成后才创建窗口。现在恢复在后台进行，界面可先使用；视频号工作等待恢复完成，避免新旧连接互相干扰。 |
| 微信连接每次要求点检测 | 后台本来持续自动检测。界面改为明确自动等待、连接就绪自动继续，手动检测仅为辅助。 |

## 普通用户安装

1. 运行 `FengshaVideoDownloader-0.8.11-setup.exe`，使用桌面快捷方式打开。
2. 公开链接可以直接识别。需要登录的平台，在账号管理打开官方登录页并完成登录检测。
3. 软件按需自动启动专用浏览器，自动准备包内组件。无需安装开发工具，也无需手动设置本地 IP。

新安装的资料放在 `%LOCALAPPDATA%\FengshaVideoDownloader\用户数据`，默认下载位置为系统“视频”文件夹下的“风沙下载”。已有安装沿用原数据库和已保存下载目录；升级不移动媒体或清除账号。CLI 与桌面读取同一套资料。

专用浏览器复用电脑已有的 Chrome 或 Edge。若两者都不存在，需先安装一种官方浏览器；组织策略禁止调试连接时，软件不能替代管理员授权。微信搜索、评论、博主采集需要已安装且已登录的电脑微信。

## “网络 IP”提示如何判断

当前源码没有统一名为“网络 IP”的错误，不能凭这个描述断定其他电脑的根因。本版消除的是浏览器本机连接参数的手工配置，不能保证第三方平台不再显示网络限制。

- 本机连接失败：由软件管理专用浏览器和动态回环端口，不要求填写公网 IP。
- 代理或公司网络限制：保持已有网络设置；不自动关闭 VPN、Clash 或安全软件，不扩大路由范围。
- 平台明确要求登录、验证码、网络验证或限制访问：在官方页面处理，保留已经取得的资料；不能通过重复确认或更改 IP 承诺解决。
- 微信首次接入及临时证书：可能出现 Windows 自己的确认。软件不自动点击系统安全确认，也不常驻受信任根证书来隐藏提示。

## 商业分发仍须完成的事项

本版改进本地安装和稳定性，不将其表述为所有客户电脑已经验收。尚需用独立干净 Windows 电脑、普通用户权限及代表性网络做实际试装和各平台业务验收。

当前构建没有配置发布者代码签名，Windows 仍可能提示未知发布者。正式商业分发应配置所属主体的有效代码签名及验证过的更新渠道；本次没有购买证书、修改系统信任设置或对外发布。签名不等同于保证任何电脑绝无提示。

Chrome 独立资料目录依据：[Chrome 官方说明](https://developer.chrome.com/blog/remote-debugging-port?hl=en)。Windows 发布者签名参考：[electron-builder 官方说明](https://www.electron.build/docs/features/code-signing/code-signing-win/)。

本版实际验证结果见 `验收-0.8.11.md`，其中明确区分本机隔离测试、打包安装验证和未完成的外部平台验收。
