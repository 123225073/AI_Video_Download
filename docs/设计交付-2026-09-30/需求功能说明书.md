# 风沙全平台视频下载器：需求与设计说明书

版本：V0.1 ｜ 日期：2026-09-30 ｜ 交付阶段：首版开发与本机验收

## 1. 产品目标与首版边界

独立 Windows 桌面应用，核心路径为“识别链接 → 选择内容 → 单条或批量下载 → 查看进度与失败原因 → 在本地媒体库找到视频”。以真实媒体落盘并可播放为下载成功条件。

默认采用 Windows x64、中文界面、本地 SQLite、安装包分发、最高可用画质、2 个下载并发、3 次自动网络重试。资料与账号会话全部使用独立目录。

五个首批平台：视频号、抖音、小红书、B站、YouTube。其他平台先保留适配接口。“全平台”是产品名称，不是已验证支持所有站点的承诺。

首版不引入课程生成、AI 聊天、字幕转写、营销、内容发布、云同步、直播录制。字幕保存、音频提取和任意转码可按后续实际需求加入。

## 2. 参考项目与复用决定

用户更正后的参考目录“风沙个人IP主页面”目前只有资产说明。根据关联记录并经源码检查，下载实现位于“风沙视频学习台”。本次只读检查了其下载 facade、任务队列、平台插件、视频号 resolver / executor 与 README，不修改旧项目，不复制用户账号或本地数据库。

已确认源码事实：旧软件使用 yt-dlp 主引擎；有 B站分P隔离；视频号采用腾讯元宝独立登录会话；视频号暂停会停止当前任务，恢复时重新解析下载，不承诺断点续传。

复用方式：参考原有模块职责与失败修复经验，独立实现简化队列与资料库；复用已安装的独立媒体工具与视频号媒体传输 worker，保留出处。旧软件历史验收不能替代新软件实测。

## 3. 开源方案评估

调研日期为 2026-09-30。以下区分官方资料声明、源码观察与本机实测；未对全部候选项目安装并测试，因此不编造下载成功率。

| 候选 | 适用模块 | 核对结果与维护快照 | 成本 / 风险 | 首版决定 |
| --- | --- | --- | --- | --- |
| yt-dlp | YouTube、B站、抖音、小红书等解析与下载 | 官方提供大量站点提取器；YouTube 完整支持依赖外部 JS 运行环境。公开仓库最近推送 2026-09-27 UTC | 低；平台规则和账号状态会变化 | 主引擎，独立子进程 |
| nexmoe/VidBee | 桌面下载流程与任务分离参考 | 旧风沙视频学习台基于此项目；当前上游含学习和 AI 模块 | 整体导入会扩大功能与依赖 | 参考职责，不整套复制 |
| Lux | 国内公开站点备用提取器 | Go CLI；官方资料提供恢复和重试功能，旧软件有受控 fallback | 中；需按来源确认画质、多段媒体与结果正确性 | 首版不自动兜底，实测后再纳入 |
| XHS-Downloader | 小红书专项适配 | API / 源码调用；Cookie 非强制但影响画质，官方标注浏览器读取 Cookie 功能已失效；推送 2026-09-20 UTC | 中；独立依赖与 GPL-3.0 边界 | 专项失败时作为候选，不宣称已集成 |
| Douyin_TikTok_Download_API | 抖音专项解析 | v5 为重写，当前重点抖音 / TikTok，不含 v4 的B站；推送 2026-09-28 UTC | 中高；整套服务涉及 PostgreSQL / Redis / Docker | 参考专项规则，不把服务栈带入桌面首版 |
| wx_channels_download | 视频号解析协议参考 | 旧软件引用腾讯元宝分享链接流程；推送 2026-09-29 UTC | 中；登录和接口依赖，MIT 附 Commons Clause | 参考已实现协议，保持独立用户授权会话 |
| Open Video Downloader | Electron 下载界面与打包参考 | Electron GUI，公开推送快照 2025-09-07 UTC | 中；已有 GUI 不符合本次六页设计 | 不整套改造 |

许可证简要核对：yt-dlp 源码为 Unlicense，打包二进制与依赖须单独看许可；FFmpeg 按实际 GPL 构建附许可证；XHS-Downloader 为 GPL-3.0；抖音 API 为 Apache-2.0；Lux 和 VidBee 主体为 MIT；视频号参考项目 MIT 附 Commons Clause。首版仅本机交付，没有对外销售或发布。

## 4. 六个页面与对应功能

| 设计稿 | 页面 | 需求编号 | 主要操作 |
| --- | --- | --- | --- |
| 01-新建下载.png | 新建下载 | F01–F04 | 手动粘贴、分享文案提取、批量识别、查看结果 |
| 02-内容选择.png | 内容选择 | F05–F08 | 集合列表、勾选、画质与目录、加入队列 |
| 03-任务中心.png | 任务中心 | F09–F14 | 下载与合并进度、暂停 / 恢复、取消、重试、详情 |
| 04-媒体库.png | 媒体库 | F15–F19 | 组合检索、标签、播放、定位、缺失文件重新定位 |
| 05-设置.png | 设置 | F20–F23 | 保存目录、并发 / 重试、归档、下载环境 |
| 06-账号管理.png | 账号管理 | F24–F29 | 多平台多账号、官方登录、会话保留、失效恢复 |

F01：支持单条链接和每行一个链接的批量输入，分享文案提取 HTTPS URL，去重。一次最多 30 个源链接。未知平台和无链接输入给出明确提示。

F02：识别域名与平台，不能因为域名包含平台字符串就视为有效；允许官方短链接。F03：识别不自动下载。F04：显示标题、平台、作者、条目数量和错误；逐个源链接显示进度，部分失败保留其余成功结果。

F05：单视频、B站分P、合集或播放列表以源引擎返回的清单呈现。默认读取 30 条，主动读取更多最多 300 条；只确认当前已获取条目，不把部分清单声称完整。F06：全选当前结果、反选、仅选未下载、按标题筛选；不可用条目不可勾选。

F07：下载前设置最高可用或 1080 / 720 / 480p 上限、保存目录、归档规则；视频号源链接决定画质，不宣称任意画质可选。F08：选择超过 30 条时确认批量数量；每条分别入队；已存在视频默认跳过，也可另存一份，不覆盖原文件。

F09：状态包括等待、下载、合并 / 校验、完成、暂停、取消、需处理、等待重试。F10：显示已下载字节、总大小、速度；未知值显示待获取，不伪造百分比。下载传输结束仍须完成合并与媒体校验。

F11：暂停停止当前任务，保留可续传片段；恢复是否续传由源协议决定，视频号明确重新下载。F12：取消仅结束对应任务及其自有进程，不影响其他任务，不删除已完成视频。F13：仅网络中断和限流有限自动重试；登录、内容失效、磁盘或权限错误转为用户处理。

F14：持久化任务，正常退出暂停活跃任务；重启将意外中断任务标为暂停并提示继续。任务详情提供可操作原因、次数、目录、脱敏诊断与原页面入口。

F15：成功且通过媒体校验的视频入库。F16：标题 / 作者 / 标签搜索与平台、作者、合集、下载时间过滤组合为 AND 条件，支持时间和标题排序、网格 / 列表。F17：使用默认播放器播放，打开所在文件夹。F18：用户编辑最多 12 个标签。F19：文件缺失显示明显状态，人工选择新位置并重新校验，不能把旧数据库记录当成文件仍存在。

F20：新保存目录对新任务生效，不搬迁已有视频。F21：并发 1–5，默认 2；网络自动重试 0–5，默认 3。F22：按平台 / 作者 / 合集归档，缺失字段使用稳定替代名称。F23：检查下载引擎、FFmpeg、ffprobe 和 JS 环境；开机启动默认关闭、仅安装版生效；不默认监听剪贴板。

F24：账号管理独立成页，每个平台允许多个备注账号，只有一个账号作为下载使用账号。F25：官方独立浏览器窗口由用户扫码或输入账号，返回点击完成登录。本应用不读取外部浏览器或旧软件账号。

F26：账号会话按账号隔离并持久化，重启保留。F27：状态区分未登录、登录中、会话已保存、最近解析成功、需要重新登录。“会话已保存”不是已验证身份；成功解析也不保证访问所有视频。

实施细节：使用 Windows DPAPI 加密保存会话快照，恢复没有持久有效期的会话 Cookie；不延长原到期时间。会话变动自动保存。官方网页拒绝内置浏览器时，允许用户主动选择 Netscape 会话文件导入，筛除其他平台与已过期条目；不自动读取外部浏览器。下载引擎所需的临时会话文件只存在对应本机账号目录，不进入页面、日志或源代码。

F28：检测到明确认证错误，标记任务使用的账号失效并引导重新登录；恢复后手动重试绑定新的选中会话。F29：退出账号需本机确认，清除本应用保存的会话，保留备注与视频。不能保证永不掉线，不使用无限请求或模拟自动登录规避平台验证。

## 5. 视觉与交互规范

浅色背景、白色内容卡、深蓝文字与蓝色操作按钮。全局左侧导航为新建下载、任务中心、媒体库、账号管理，下部设置与帮助。字体优先微软雅黑 UI，中文标题 32px，主体 12–15px；内容间距约 24px，卡片圆角 10px。

桌面最小窗口 1080×720；宽屏内容与右侧详情 / 选项并列，窄屏缩小侧栏、媒体库改为两列。输入、按钮、复选框均可键盘操作，具有清晰焦点与禁用状态。设计稿中的封面、数字、平台状态是示例数据，不灌入正式资料库。

生图提示词保存在同目录。原五张稿是在新增账号需求前生成；实施时所有页面的侧栏统一加入账号管理。图片文字或示例细节与软件不同，以本说明书和真实状态为准。

## 6. 架构与数据结构

React 界面 → 限定 preload API → Electron 主进程服务 → 平台适配器 / 下载队列 → yt-dlp 或视频号传输 worker → FFmpeg / ffprobe → 本地媒体库。

界面不直接访问 Node、磁盘或账号 Cookie。平台适配只返回标准视频条目与可下载能力；队列负责并发、状态与重试；文件管理负责归档、命名与实际文件检查。

| 实体 | 主要字段 | 用途 |
| --- | --- | --- |
| VideoItem | key、platform、sourceId、part、url、title、author、collection、duration、thumbnail、height、accountId | 标准化单视频身份，B站分P分开 |
| DownloadTask | id、item、options、status、attempts、progress、error、retryAt、createdAt、completedAt | 可恢复下载记录与每次尝试 |
| Media | id、filePath、size、duration、height、downloadedAt、tags、来源条目字段 | 实际本地视频与组合检索 |
| Settings | savePath、quality、archive、concurrency、retries、skipDuplicates、autoStart | 本机下载偏好 |
| Account | id、platform、name、status、lastSync、lastVerified、message | 不含密码 / Cookie 的账号状态 |
| ActiveAccount | platform、id | 每个平台选择一个账号 |
| Session | 独立 Electron 会话目录 | 登录资料与账号元数据隔离 |

SQLite 使用 records(kind,id,data) 保存首版标准实体，复合主键区分实体与身份；参数化操作，schema 版本 1，磁盘保存采用临时文件、fsync 与原子替换。资料库路径为 `%APPDATA%\fengsha-video-downloader\library.sqlite`。

文件名先放内容标识，再放画质与清理后的标题。Windows 保留名、非法字符和超长标题经过处理。同标题不覆盖，B站分P的身份参与 key。媒体库入库前检查输出文件存在且 ffprobe 有视频流；验收使用完整解码进一步核对代表性样本。

## 7. 失败分类与恢复

| 故障 | 自动行为 | 用户下一步 |
| --- | --- | --- |
| 登录缺失 / 失效 | 停止盲目重试，标记对应账号 | 官方登录，再重试 |
| 限流 / 412 / 429 | 有限冷却重试 | 等待或降低并发 |
| 网络 / 5xx / 超时 | 递增等待、有限重试 | 恢复网络后继续 |
| 链接删除 / 不可用 | 明确失败 | 检查原页面、更新链接 |
| 磁盘不足 / 写入拒绝 | 停止任务 | 释放空间 / 更换目录 |
| 合并 / 媒体校验失败 | 不标为完成、不入库 | 检查组件、重试 |
| 平台规则变化 | 标出解析失败 | 更新适配器或提供失败样本 |
| 程序退出 / 崩溃 | 下次恢复为暂停 | 明确继续或重新下载 |

不会为了提高表面成功率绕过 DRM、付费墙或访问控制；无法下载时给出实际失败状态。

## 8. 分阶段验收与平台矩阵

阶段 A：六页桌面界面、账号页面、独立资料目录、环境检查。阶段 B：真实识别 / 下载 / 合并 / 校验 / 入库、批量选择、任务恢复。阶段 C：五平台代表链接逐条验证，包括所需登录；更新平台支持矩阵。阶段 D：Windows 安装包、桌面快捷方式、安装版启动与数据保留检查。

| 平台 | 已接入入口 | 本次首版验收要求 | 不应默认声称 |
| --- | --- | --- | --- |
| YouTube | yt-dlp + JS 环境、官方账号会话 | 公开单视频、一个播放列表、媒体完整解码 | 任何网络环境均可下载、所有账号登录方式均可用 |
| B站 | yt-dlp、分P独立身份、官方会话 | 单视频、指定分P、集合与实际画质 | 无登录也能取得所有高画质 |
| 抖音 | 分享链接提取、yt-dlp、独立账号 | 短链 / 长链、单视频，真实账号条件记录 | 作者主页 / 合集无限量获取 |
| 小红书 | 分享链接提取、yt-dlp、独立账号 | 有效视频笔记链接，画质与会话要求记录 | 图文内容自动当成视频或全部合集可用 |
| 视频号 | 元宝会话解析、媒体 worker | 用户新登录、完整视频、失效与重试 | 无账号任意下载、原画质及断点续传保证 |

支持矩阵必须随真实验收更新为“已测试可下载 / 条件支持 / 失败待修复 / 待测试”，并记录样本、日期、引擎版本、账号条件、输出大小与媒体校验。离线测试和本地 HTTP 测试媒体不能冒充五平台实测。

首版公共验收：并发限制正确；单任务失败不破坏其余任务；同名和重复处理正确；关闭 / 重启保留设置、账号备注、任务与媒体；文件缺失能够恢复定位；正式资料库无示例数据；旧应用资料未改写。

需要用户参与的关键事项：五个平台的代表性可保存链接与必要官方扫码登录。没有提供账号的情况下交付登录入口并明确条件，不把账号相关下载标为已验证。
