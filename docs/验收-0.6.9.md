# 0.6.9 验收与验证边界

## 结果

- 创作控件改为文案＋图片、仅文案、仅图片三个并列页签；一个紧凑操作面板，参考依据是一行下拉框。页签独立保留方向与参考选择；键盘切换、原稿对照、流式输出及历史恢复保留。
- 文案默认轻微润色，保留原意、求助／庆祝等诉求、口吻、标题钩子、篇幅和排版。短文异常扩写拒绝覆盖原稿；平台表情和话题编码转成正常格式。
- 真实已配置文本模型验证用户提供的短篇求推荐：返回“求推荐好用的减肥产品！”，正文仍是生娃后想瘦、靠自己不太行、求推荐的简短表达，保留emoji及话题，没有改成科普或评测。仅测试文案，未修改用户稿件、未请求图片模型。
- YouTube 旧日期排序参数已不符合当前官网过滤选项。改用官网时间筛选，对较早的日期范围使用更宽的筛选；模糊日期从当前视频微格式核验，不取推荐视频的日期。真实最近一个月读取5条，4条有可验证日期符合范围，1条日期待确认而未冒充结果。
- 抖音真实页面进入官方验证码，暂停并显示验证窗口；页面加载失败不当作空结果。本次未完成真实抖音作品采集验收。
- 视频号增加固定微信启动协议的自动尝试；等待连接时显示明确弹窗，能打开微信、取消、接通后继续。隔离场景验证了这些行为。真实自动唤起的系统命令测试被自动审批策略阻止，未确认当前机器的协议能够自动进入视频号；不宣称完全无人工或真实视频号搜索已验收。

## 验证

245 项单元回归、21项二创界面检查、原生取消／日期／会话、连接提示与恢复、抖音验证错误反馈、媒体预览和版本竞态检查。均通过。原生会话测试在并行界面操作中曾错过短暂的日期读取阶段；单独复跑，并确认真实窗口脚本已加载后取消，结果通过。真实平台验证不发送私信、不发布内容、不改系统代理或证书。

## 技术依据

现有采集组件的[官方 MCP 说明](https://ltaoo.github.io/wx_channels_download/feature/mcp/commands.html)要求微信页面连接。开源 [wx_channel Windows 打开器](https://github.com/nobiyou/wx_channel/blob/main/internal/lifecycle/opener_windows.go)记录协议兼容性差异，并使用特定窗口位置点击；本应用没有照搬固定坐标或导入第三方账号服务。实现仅使用固定注册协议，并保留明确的失败引导。真正脱离微信的搜索需另行评估数据提供方／登录协议，当前没有新增第三方凭据或付费接口。
