# 0.8.2 修复与验收

本版本将视频号链接识别、作者作品读取及视频转图文的修复一起交付。保留原口播、校对稿和用户编辑，默认不生成图片。

## 修复内容

- Clash 本机控制支持 TCP 与 Windows Verge 命名管道，继续使用独立临时分流及恢复机制。
- 分享链接与作品 ID 使用同一详情接口适配；作者作品分页也从已加载官方模块恢复接口。已有可靠分享作者信息直接复用，不再次连接微信识别作者。
- 页面连接、适配版本和实际接口能力分别核对，升级适配时限次刷新。
- 页面脚本使用内容指纹文件名，探针核对实际运行指纹；新版适配在已授权分流内支持一次本页面刷新，刷新确认本身不视为接口就绪。
- 系统代理核对按四项设置的存在状态和值比较，修正 PowerShell 哈希表字段顺序不同造成的偶发误报。
- 英文转中文图文修正泛指数词及单位等价的误判；真实数量、单位与事实变化仍须通过校验。失败候选保留正文、分页及具体原因，不覆盖已保存成稿。
- “创作设置”弹窗统一参考稿、页数、画风、语言和配图开关。主布局显示流式正文与分页，配图默认关闭。
- 保留校对后再二创的顺序、原视频播放、取消、任务切换、保存绑定及中断恢复。

## 验证方式

本地单元测试、隔离 Electron 实际 IPC/React 测试、真实接口验收和安装后验证分别记录；隔离模型测试不能替代真实模型结果。

可重跑：`node --test tests/*.test.js`、`node scripts/video-workbench-races-e2e.mjs`、`node scripts/video-article-082-e2e.mjs`、`node scripts/content-recovery-e2e.mjs`。

## 视频号真实验收边界

Clash 当前使用本机命名管道控制，已完成真实只读核对；两次限时连接结束后四项系统代理的存在状态和值及分流规则序列均恢复。

本次部署的新脚本配置及文件已核对，微信活动页面仍返回旧 v3 探针，未达到 v4 指纹和作者作品接口就绪条件，因此分享作者及作品分页的真实平台验收**未通过，不宣称已彻底修复**。电脑操作工具保持 Esc 停止状态，无法代替用户执行首次页面刷新；人工刷新请求已提出。

反复出错的已确认代码问题包括：TCP 控制接口假设不适用于本机命名管道；分享详情与作品 ID 详情的适配不一致；连接状态未证明接口能力或运行脚本已更新；代理快照的字段顺序被误当作设置变化。上述代码问题及异常恢复已有回归覆盖。微信的页面接口依赖其实际加载的登录页面和模块，仍须通过首次新版脚本的真实页面验收；不能承诺第三方平台后续更新永远不会影响接口。

视频公开分享链接解析与已有文件转录路径与关键词搜索、作者作品列表分别处理；已有可信分享作者信息直接复用，不能将一个链接下载成功当作作者列表接口已通过。
