# 0.8.4 视频号适配载入与组件生命周期修复

## 已确认的问题

截图中的外部适配资源加载失败后，上游原始处理器仍直接调用 `WXU.API2.finderSearch`。原有新版适配虽能按能力找回官方模块，但没有成功载入时不起作用。

实机发现采集 API 端口 2022 与代理端口 2023 分属不同进程；配置重启后旧代理仍持有原脚本。重复刷新不能保证拿到新版。经用户确认，仅结束已核对安装路径的 5 个残留采集组件，未结束微信、Clash 或其他程序。

固定上游 v260907 的 `proxy/config` 在 `restart:true` 时总会停止再启动代理，不以 `proxy.enabled:false` 为停止条件。以前的退出实现误把该请求当作停止。此外接口通过事件总线异步处理，返回成功不能证明端口释放。

## 本次修改

- 使用上游 `inject.contentScript` 把本机适配直接写入拦截后的 HTML，保留源码指纹核对和按实际能力读取官方接口。
- v260907 会把空 `globalScript` 解析为工作目录，因此用本工具保留的不存在路径禁用外部脚本。该路径若被占用，明确停止而不覆盖文件。
- 重载组件配置前调用明确的 `service/stop`，核对服务已停止且端口不再监听；没有释放就不继续重载。
- 任务结束先恢复系统网络和分流，再停止采集代理；后台恢复守护也使用明确的停止接口。失败保留状态以便重试。
- 停止状态接口还会查询 Windows 证书库。临时证书移除后原 2.5 秒上限过短，改用已有 15 秒接口等待时间，避免端口已关闭却误报恢复失败。
- 保留严格作者 ID、原作品核验、已有作品和续读位置，不以头像或昵称代替身份确认。

## 验证记录

740 项完整串行测试全部通过。最后的恢复守护和状态等待修改后，连接、部署与 PowerShell 状态恢复 48 项定向测试全部通过。已完成的失败复现及定向回归：外部资源不可用时适配仍执行；停止端口前禁止重载；停止接口不能使用 `restart:true`；网络恢复先于代理停止、失败可重试。另有适配与作者读取 36 项通过，不叠加计算为独立业务验收。

使用真实内置组件、隔离工作目录与随机本机端口，实证旧停止请求返回后端口仍监听；新版停止方法连续两轮启动/停止都通过。本项未连接外部平台、未安装系统证书或改变系统代理。

第一次清理残留后的尝试中，临时测试仍采用旧“禁用并重启”操作，复现两个端口分属新旧进程。修正为真正停止后，后续实机检查两个端口归属同一个组件进程。真实作品读取等待微信视频号窗口连接。电脑操作工具收到 Esc 停止信号后已停止自动操作。

用户重新打开并刷新页面后，真实识别 `戏里戏外说2026` 成功，作者 ID 已核验。连续 8 次无缓存探测均为适配 v4、指纹 `d942281b07fd`，搜索、详情与作者作品能力均可用。从真实接口读取作品，再按本地续读位置读取，共两批各 5 条，10 条作品 ID 无重复。第二批使用第一批保留的待处理记录，并不代表额外一次远端分页调用；未遍历全量作品或批量下载媒体。

最终读取与恢复全程退出码 0，Clash 规则恢复，2023 端口停止监听。系统代理启用值、服务器地址和 PAC 保持；`ProxyOverride` 在任务前后及任务结束后的只读检查中仍有独立变化，因此四字段全等检查为 false，不宣称全部系统设置字节不变。本次 routed 路径没有写入该字段，未覆盖后来的设置。详见 `live-result.json` 与 `network-final.json`。

期间一次恢复状态查询超时；重试确认端口已关闭。改用 15 秒超时后的真实读取正常结束，状态查询耗时约 2.45 秒。最终打包已生成安装包及 blockmap，但工具清理临时 `.nsis.7z` 时遇到 EBUSY；以最终安装退出码、安装载荷逐文件核对和启动验证判定交付，保留构建日志。
